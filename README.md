# parser-tg

Лёгкий сервис, который читает выбранные Telegram-каналы через выделенный пользовательский
аккаунт, ищет упоминания заданных комплектующих и пересылает исходные публикации основному
аккаунту.

## Как работает фильтрация

Текст и подписи приводятся к единому регистру и формату: `ё` заменяется на `е`, знаки
пунктуации и дефисы становятся пробелами, а границы между буквами и числами разделяются.
Сначала проверяется точная фраза, затем — локальное fuzzy-сравнение. Числа должны совпадать
строго, поэтому правило `RTX 4070 Ti` не примет `RTX 5070 Ti`.

`exclude` отключает весь фильтр, когда соответствующая точная фраза присутствует в посте.
`require_any` задаёт дополнительное условие: кроме совпадения по `aliases`, в публикации
должен встретиться хотя бы один разрешённый бренд, сокет, размер или серия из списка.
Цена и размер скидки не анализируются. Публикации без текста или подписи не совпадают.
Исключение — тестовый конфиг с пустым `filters`: он пересылает все новые публикации,
включая посты без текста и подписи.

## Подготовка

1. Создайте `api_id` и `api_hash` для выделенного аккаунта на
   [my.telegram.org](https://my.telegram.org) → **API development tools**.
2. Подпишите выделенный аккаунт на нужные каналы.
3. С основного аккаунта один раз напишите выделенному аккаунту.
4. Создайте локальные файлы:

   ```bash
   cp .env.example .env
   chmod 600 .env
   ```

5. Заполните `.env` и `config/rules.yaml`. `.env` исключён из Git, а правила намеренно
   версионируются вместе с кодом.

Источник можно указать публичным username или числовым Telegram ID. Для приватного канала
обычно удобнее узнать ID после входа в аккаунт и записать его числом. Получатель задаётся
только положительным числовым ID пользователя: сервис отклоняет username, группы, каналы
и ботов, чтобы исключить пересылку не тому адресату.

## Первый вход и запуск в Docker

Соберите образ и интерактивно авторизуйте выделенный аккаунт:

```bash
docker compose build
docker compose run --rm parser login
```

Telegram запросит номер, одноразовый код и, если включена, облачный пароль 2FA. Они не
сохраняются в Git; постоянная MTProto-сессия останется в Docker volume `parser-data`.

После успешного входа запустите сервис:

```bash
docker compose up -d
docker compose logs -f parser
```

Обновление вручную:

```bash
git pull
docker compose up -d --build
```

Volume с сессией и SQLite при пересборке сохраняется. Не публикуйте `.env`, `.session` и
содержимое volume. Для выделенного аккаунта рекомендуется включить 2FA.

## Локальная разработка

Нужны Python 3.13+ и [uv](https://docs.astral.sh/uv/):

```bash
uv sync
uv run parser-tg validate config/rules.yaml
uv run pytest
uv run ruff check .
```

Локальная авторизация и запуск используют те же переменные окружения:

```bash
set -a
source .env
set +a
uv run parser-tg login
uv run parser-tg run
```

## Правила и эксплуатация

Изменения YAML применяются после перезапуска:

```bash
docker compose restart parser
```

Для временного режима «пересылать всё» установите в `.env`:

```env
CONFIG_PATH=/app/config/rules.test.yaml
```

После теста верните `/app/config/rules.yaml` и перезапустите сервис.

Каждый пост каждого канала пересылается отдельно. Уже доставленный пост не отправляется
повторно после reconnect или рестарта. Отредактированный ранее неподходящий пост проверяется
заново; уже доставленный после правки не пересылается. Для альбома анализируются объединённые
подписи, а пересылается весь альбом. Если канал запрещает форвард, сервис отправляет фильтры,
название источника и ссылку на публикацию.

Логи не содержат полный текст сообщений или секреты. Обновления Telegram обрабатываются
последовательно, поэтому длительное ожидание не создаёт отдельную задачу на каждую следующую
публикацию. При временном `FloodWait` до пяти минут сервис ждёт и повторяет операцию; более
длинное ограничение записывается как ошибка доставки, и пост будет доступен для повторной
попытки при следующем Telegram-событии.
